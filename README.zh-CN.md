# Risk-Aware Decision Routing

**复核时间有限时，哪些灾害图片最值得再看一眼？**

[English](README.md) · [完整结果](reports/results.md) · [方法说明](docs/method.md) · [复现指南](docs/reproduction.md)

这个项目从 MEDIC 灾害图片分类出发，研究一个具体问题：模型无法避免所有错误，
那应该怎样分配有限的复核资源，尽量减少代价较高的错误？

系统保留已有的 ViT，比较按不确定性复核、学习式模型选择和尾部风险路由。
另设一个独立的开发集审查部分，决定是否有足够证据采用更复杂的策略。

![相同复核预算下的成本与严重错误比较](reports/figures/operating_point.png)

## 实验结果

在去重后的 **15,634 张测试图片**上，允许 **20% 的图片进入复核**：

| 策略 | 每张图片的加权错误成本 ↓ | 剩余严重错误 ↓ |
|---|---:|---:|
| 原模型＋熵排序 | **0.0614** | 37.0 |
| 严重程度加权预测头＋熵排序 | 0.0697 | 27.0 |
| MoE 平均风险路由 | 0.0652 | 29.7 |
| MoE 尾部风险路由 | 0.0828 | **24.3** |
| 带采用条件的默认策略 | **0.0614** | 37.0 |

尾部策略留下的严重错误减少了约 **34%**，但总体加权成本增加了约 **35%**。
三个随机种子的审查结果都不足以支持切换，所以默认仍使用熵排序。

这个项目展示的是一个可测量的取舍：更关注严重错误，会改变剩余错误的分布，
却不一定降低总体成本。结果是三个路由训练种子的均值，图像主干固定不变；
并不是重新训练了三个 ViT。

成本 1/3/8 是示例权重。表中假设复核能纠正被转交的案例，未采集真实人工结果。
[实验报告](reports/results.md) 同时给出了人工复核不完美时的敏感性分析。

## 代码做了什么

- 按图片内容去重，检查训练、开发、测试集之间的重叠。
- 提取固定 ViT 特征，训练普通和严重程度加权的预测头。
- 用小型 MoE 预测错误成本分布，比较平均风险和条件 CVaR。
- 精确限制每批复核数量；证据不足时回退到基线。
- 在相同的 3,000 张真实图片上执行模糊、JPEG 压缩测试。
- 保存 CSV、实验出处和五组 PNG/SVG 图表，支持重复运行。

这里的 MoE 是风险预测器的混合，不是大语言模型的稀疏 MoE。
采用条件也只是经验检查，不构成分布变化下的安全保证。

## 从哪里开始

第一次了解项目，先看 [英文 README 的安装步骤](README.md#get-started)，
再读 [方法说明](docs/method.md)。已提交的报告不需要数据集即可查看；
运行图片实验还需要本地 MEDIC 和原始 ViT 权重，二者都没有上传。

安装后可以运行：

```bash
python -m unittest discover -s tests -v
```

已有本地数据和权重时：

```bash
bash scripts/reproduce.sh --full
radr-route --feature-cache out/features/test.npz --limit 20
```

用浏览器打开本地 `reports/index.html`，可以连续浏览图表。GitHub 上也可直接
查看 [结果文档](reports/results.md) 和 [图片](reports/figures/)。

## 适合怎样介绍这个项目

重点是 **稳健决策系统与实证 AI safety**：哪些案例需要升级处理、复核预算
怎样影响错误，以及什么时候应当保留简单基线。实现与结果都可以检查，
负结果也保留在 [pilot](reports/pilot/) 中。

当前证据仍是探索性的：历史模型使用开发集选择权重，测试集也已在开发中查看；
数据去重没有覆盖视觉近似图片。下一步最有价值的是真实复核结果和新灾害事件上
的独立评估。关于 MoE、CVaR 和 learning to defer 的论文联系与边界，见
[相关工作](docs/related-work.md)。
